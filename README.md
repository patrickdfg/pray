# 기도숲 · Pray Garden

함께 기도하고 작은 실천을 기록하며 아기 양 ‘소망이’의 정원을 키우는 반응형 웹 앱입니다. 참고 이미지의 게임형 습관 관리에서 아이디어를 얻고, 일러스트와 UI는 새로 제작했습니다.

## 현재 상태

- **바로 실행 가능한 체험 모드**: Firebase 환경변수가 없으면 자동으로 시작합니다. 예시 팀과 기도·할 일 데이터가 제공되며, 변경 내용은 현재 브라우저에 저장됩니다.
- **Firebase 연결 코드 포함**: Google 로그인, 초대 링크, 초대한 사람 아래로 연결되는 팀원 관계, 팀 공유, 실시간 동기화, 서버에서 검증하는 보상을 구현했습니다. 실제 Firebase 프로젝트가 없어 운영 배포 및 실제 Google 계정 간 테스트는 아직 하지 않았습니다.
- Android/iOS 네이티브 앱이 아닌 모바일 웹 앱입니다.

## 실행

Node.js 22.12 이상을 권장합니다.

```bash
npm ci
npm run dev
```

터미널에 출력된 주소를 엽니다. 같은 Wi-Fi의 휴대폰에서는 터미널의 Network 주소로 체험할 수 있습니다. 실제 팀 초대에는 배포된 HTTPS 주소가 필요합니다.

```bash
npm test
npm run build
npm --prefix functions ci
npm --prefix functions run build
```

## 사용 흐름

1. 오늘의 숲에서 **새로운 씨앗 심기**를 누릅니다.
2. 기도 또는 할 일을 선택하고 제목과 자세한 내용을 적습니다. 기본은 팀 전체 공유입니다.
3. 비밀로 설정하면 제목·내용·감동 댓글·횟수 모두 현재 브라우저에만 저장합니다.
4. 목록은 제목 중심으로 보여 줍니다. 제목을 열면 상세 이야기와 감동 댓글을 나눌 수 있습니다.
5. 기도·실천할 때 버튼을 눌러 횟수를 남깁니다. 실수로 연속 탭하는 것을 막기 위해 3초 간격을 둡니다.
6. 상세 화면의 **이 여정을 마무리하고 싶어요**에서 1~5단계 체감을 남깁니다. 팀에서 받은 항목도 각자가 마무리할 수 있으며, 다른 팀원의 여정은 계속됩니다.
7. 성장 기록에서 평균 횟수와 달성도 분포를 확인하고, 잎사귀로 꽃밭·랜턴·분수 장식을 모읍니다. 구매한 장식은 오늘의 숲에 나타납니다.

| 단계 | 체감 달성도 | 표현                   |
| ---- | ----------- | ---------------------- |
| 1    | 0%          | 아직 기다리는 중       |
| 2    | 25%         | 작은 변화가 있어요     |
| 3    | 50%         | 절반쯤 이루어졌어요    |
| 4    | 75%         | 거의 이루어졌어요      |
| 5    | 100%        | 감사해요, 이루어졌어요 |

5단계로 마무리한 기도와 할 일을 각각 모아, 마무리 시점의 누적 횟수를 평균 냅니다. 데이터가 없으면 0 대신 ‘아직 없어요’로 표시합니다. 이 통계는 사용자의 체감 기록이며 기도의 효과나 인과관계를 측정하는 수치가 아닙니다.

## 팀과 보상 규칙

- 첫 팀을 만든 사람이 팀장입니다. 팀장이 등록한 항목은 ‘팀장에게서 왔어요’로 구분됩니다.
- 팀원도 공유 기도와 할 일을 등록하고, 다른 사람을 초대할 수 있습니다. 초대한 사람의 UID가 새 팀원의 `parentUid`로 저장됩니다. 기존 팀원의 부모 관계는 초대 링크를 다시 열어도 바뀌지 않습니다.
- 현재 버전은 계정당 한 팀입니다. 공유 항목과 댓글은 같은 팀 전체에서 보입니다. 부모 관계는 조직 관계를 나타내며 별도 비공개 하위 그룹을 뜻하지 않습니다.
- 초대는 무작위 48자리 토큰이며 7일 또는 신규 가입 100회까지 유효합니다. 링크는 자동 발송하지 않고 복사해서 직접 공유합니다.
- 공유 항목 기록은 10 XP + 2 잎사귀, 마무리는 단계와 관계없이 20 XP + 5 잎사귀입니다. 100 XP마다 레벨이 올라갑니다.
- 사용자별 마무리와 중복 활동 이벤트는 서버 트랜잭션으로 검사합니다. 마무리한 항목의 통계는 당시 횟수로 고정됩니다.
- 비밀 기록은 서버로 전송하지 않으므로 계정 XP와 잎사귀를 지급하지 않습니다.

## 비밀 항목 저장

비밀 항목은 `localStorage`의 `pray:secrets:<사용자 UID>`에 저장합니다. 체험 계정과 실제 계정은 별도 키를 사용하고 로그아웃하면 이전 계정의 항목을 화면에서 제거합니다. Firebase 클라이언트 쓰기는 차단되어 있고, 서버의 공유 항목 생성 API도 비밀 항목을 거부합니다.

이는 **해당 브라우저 프로필 안의 로컬 저장**이며 암호화 금고가 아닙니다. 브라우저 데이터 삭제, 다른 브라우저 또는 기기 변경 시 자동 복구되지 않습니다. 연결 및 개인정보 화면에서 JSON 백업을 다운로드할 수 있습니다. 현재 백업 다시 가져오기 UI는 없습니다.

## Firebase 연결

1. Firebase 프로젝트를 만들고 Authentication에서 **Google** 제공자를 켭니다. 웹 앱을 등록하고 Firestore 데이터베이스를 생성합니다.
2. `.env.example`을 `.env.local`로 복사하고 웹 앱 구성의 `apiKey`, `authDomain`, `projectId`, `appId`를 채웁니다. 웹 앱 구성은 클라이언트용 값이며 서비스 계정 비밀키를 넣으면 안 됩니다.
3. Firebase CLI를 설치하고 해당 계정으로 로그인합니다. 프로젝트와 과금 설정을 확인합니다. Cloud Functions 운영 배포에는 Blaze 요금제 및 사용량 비용이 필요할 수 있습니다. 이 저장소는 프로젝트나 과금을 자동으로 생성하지 않습니다.
4. 프런트엔드와 함수를 빌드한 다음 본인의 프로젝트 ID를 명시하여 배포합니다.

```bash
npm ci
npm --prefix functions ci
npm run build
npm --prefix functions run build
npx firebase-tools login
npx firebase-tools deploy --project YOUR_PROJECT_ID --only firestore:rules,functions,hosting
```

5. Authentication의 승인된 도메인에 실제 Hosting 도메인을 확인하고 추가합니다. 로컬 로그인 테스트 시 `localhost`도 확인합니다.
6. 서로 다른 Google 계정 두 개로 팀 생성 → 초대 → 가입 → 공유 항목 → 기록 → 각자 마무리를 테스트합니다. 다른 팀 계정의 접근 거부도 운영 연결 후 확인해야 합니다.

리전은 `asia-northeast3`입니다. 환경변수 변경 후에는 서버 재시작 또는 재빌드가 필요합니다. `firestore.rules`도 반드시 함께 배포하세요.

## 데이터와 권한

```text
profiles/{uid}                       개인 XP, 잎사귀, 장식, 현재 팀
teams/{teamId}                       팀장, 팀 이름
teams/{teamId}/members/{uid}         역할, 초대한 사람
teams/{teamId}/items/{itemId}        공유 항목, 댓글, 사용자별 마무리
teams/{teamId}/items/{itemId}/actors/{uid}    기록 횟수 및 쿨다운
teams/{teamId}/items/{itemId}/events/{eventId} 중복 이벤트 방지
invites/{token}                     팀, 초대한 사람, 만료, 사용 횟수
```

Firestore 클라이언트는 본인 프로필 및 가입한 팀의 항목·팀원만 읽을 수 있습니다. 직접 쓰기는 모두 거부하며, 인증된 Google 사용자만 Callable Function을 호출할 수 있습니다. 초대 토큰과 활동 하위 컬렉션은 클라이언트가 직접 읽을 수 없습니다. 서버는 팀 가입 여부, 입력 길이·종류, 개인별 중복 완료, 보상, 장식 잔액을 검증합니다. 댓글은 한 항목당 최대 100개입니다.

## 검증

- `npm test`: 기록 간격, 완료 범위, 평균 계산, 인증 거부, 초대 부모 관계, 만료 초대, 다른 팀 전환 거부, 팀 외 접근 거부, 비밀 항목 거부, 중복 보상, 개인별 마무리, 장식 구매, 댓글 작성자 검증 — 총 12개 테스트.
- 서버 테스트는 인메모리 Firestore 어댑터를 사용합니다. 실제 Google OAuth, Firestore 규칙과 트랜잭션 동시성에 대한 에뮬레이터·운영 통합 테스트를 대체하지 않습니다.
- `npm run test:browser`: 개발 서버 실행 상태에서 Chrome으로 등록·횟수·댓글·완료·보관함·비밀 저장 및 새로고침·모바일 가로 넘침·초대 안내를 확인합니다. Chrome이 필요합니다. 화면은 무시된 `test-results/`에 저장합니다.
- 프런트엔드 및 Functions TypeScript 빌드 확인. 의존성 lockfile과 GitHub Actions 검사 포함.

## 파일

- `src/main.tsx`: 화면과 체험 모드
- `src/domain.ts`: 기록, 완료, 통계
- `src/cloud.ts`: 선택적 Firebase 연결
- `functions/src/index.ts`: 인증·초대·팀 공유·기록·보상 서버
- `firestore.rules`: 팀/개인 접근 규칙
- `public/garden.webp`: 새로 생성한 소망이와 기도 정원 일러스트

서비스 알림·반복 일정·푸시 알림·앱스토어 패키징은 현재 버전에 포함하지 않습니다.
