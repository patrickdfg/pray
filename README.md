# 기도숲 · 함께 기도하고, 함께 자라요

기도와 작은 실천을 기록하고 서로를 응원하는 모바일 웹 앱입니다. 포근한 토끼의 방, 아기 양 **소망이**, 파스텔 핑크·크림·라벤더 카드로 오늘의 마음을 나눕니다. 경험치, 레벨, 코인과 수집 아이템도 함께 자랍니다.

2026-10-23 디자인 리빌딩과 편집 복원, 검증 결과 및 **공유 편집의 Firebase 규칙 배포 대기 사항**은 [REBUILD-NOTES.md](REBUILD-NOTES.md)를 확인해 주세요.

**[기도숲 앱 열기](https://patrickdfg.github.io/pray/)** — GitHub Pages에 배포되어 있습니다. **Google로 가입·로그인**을 누르면 Google 계정으로 시작합니다. 처음 로그인할 때 프로필을 자동 생성하고, 다음부터는 같은 계정으로 로그인합니다. 이메일/비밀번호 가입은 제공하지 않습니다.

계정 없이 둘러보려면 **[체험 모드](https://patrickdfg.github.io/pray/?demo=1)**를 사용합니다. 체험 기록은 브라우저에만 저장되며 실제 팀 데이터와 분리됩니다.

`main` 브랜치에 코드를 올리면 GitHub Actions에서 빌드와 규칙 테스트를 통과한 뒤 Pages에 자동 배포됩니다. Pages 빌드만 `/pray/` 경로를 사용하며 Firebase Hosting 빌드는 루트 경로를 사용합니다. 공개 주소에서도 등록·기록·댓글·마무리·비밀 저장·모바일 화면·보상 구매를 브라우저로 검증했습니다.

## 무료 운영 구조

**Firebase Spark(결제 계정 없이 시작하는 무료 요금제)**에 맞춰 구현했습니다. Cloud Functions, 유료 서버, Cloud Storage를 사용하지 않습니다.

- GitHub: 앱 코드와 캐릭터 이미지 관리
- Firebase Hosting: 웹 앱 배포
- Firebase Authentication: Google 로그인
- Cloud Firestore: 팀, 초대, 공유 퀘스트, 댓글, 보상 기록
- Firestore Security Rules + 클라이언트 트랜잭션: 가입 관계·동시 기록·보상·접근 권한 검증
- 기기 브라우저 `localStorage`: 비밀 기도·비밀 할 일

운영 Firebase 프로젝트는 `pray-quest`입니다. Google Authentication과 서울 리전 Firestore Standard를 사용합니다. 웹 앱 공개 구성은 GitHub Actions 저장소 변수 네 개로 전달하며, 서비스 계정 비밀키는 배포하지 않습니다. 환경변수가 없는 로컬 실행은 자동으로 체험 모드가 됩니다.

Spark는 서비스별 무료 한도가 있습니다. 전체 프로젝트의 무료 할당량을 소진하면 요청이 거부되거나 서비스가 일시 제한될 수 있습니다. 프로젝트를 Spark로 유지하고 결제 계정을 연결하지 않으면 유료 초과 사용으로 자동 전환되지 않습니다. 아래 앱 자체의 제한은 사용량을 줄이는 장치이며, Firebase 전체 무료 할당량 안에서 항상 서비스가 계속된다는 보장은 아닙니다.

공식 기준: [Firebase 요금제](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans), [Firestore 무료 할당량](https://firebase.google.com/docs/firestore/quotas#free-quota).

## 기능

1. **새 퀘스트 만들기**에서 기도/할 일, 제목과 자세한 내용을 등록합니다.
2. 기본은 팀 전체 공유입니다. 팀장이 등록하면 팀장에게서 온 항목으로 구분됩니다.
3. 비밀 항목은 제목·내용·댓글·횟수 모두 기기에만 저장하며 Firestore로 보내지 않습니다.
4. 목록은 제목 중심입니다. 항목을 열면 상세 내용과 감동 댓글을 확인할 수 있습니다.
5. 기도/실천 버튼을 누르면 횟수가 쌓이고, 토끼와 소망이의 부드러운 반응과 +10 XP 효과가 나타납니다. 경험치에 따라 성장 막대가 채워지고 100 XP마다 레벨이 올라갑니다.
6. 완료할 때 개인별로 1~5단계의 체감 달성도를 기록합니다. 다른 팀원의 여정은 계속됩니다.
7. 성장 기록에서 기도/실천별 평균 횟수, 달성도 분포, 레벨과 수집품을 확인합니다.

| 단계 | 체감 달성도 | 표현                   |
| ---- | ----------- | ---------------------- |
| 1    | 0%          | 아직 기다리는 중       |
| 2    | 25%         | 작은 변화가 있어요     |
| 3    | 50%         | 절반쯤 이루어졌어요    |
| 4    | 75%         | 거의 이루어졌어요      |
| 5    | 100%        | 감사해요, 이루어졌어요 |

5단계로 마무리한 항목의 당시 누적 횟수를 기도와 할 일별로 평균 냅니다. 표본이 없으면 ‘아직 없어요’로 표시합니다. 체감 기록을 보여 주며, 기도의 효과나 인과관계를 측정하지 않습니다.

## 무료 버전의 앱 한도

| 항목                | 한도                                     |
| ------------------- | ---------------------------------------- |
| 계정당 팀           | 1개                                      |
| 팀원                | 팀당 최대 100명                          |
| 공유 퀘스트         | 완료 보관함 포함 팀당 최대 100개         |
| 댓글                | 공유 퀘스트당 최대 100개, 댓글당 1,000자 |
| 보상 활동           | 계정당 하루 200회, 한국 시간 자정 초기화 |
| 같은 항목 기록 간격 | 사용자별 3초                             |
| 초대                | 생성 후 약 7일, 신규 가입 최대 100회     |
| 목록 읽기           | 쿼리당 최대 100개                        |

계정당 하루 200회는 기도/실천과 마무리 보상 횟수의 합계입니다. 댓글과 조회를 포함한 Firebase 전체 사용량 한도와는 별개입니다. 날짜는 서버 규칙에서 한국 시간 기준으로 검증합니다.

공유 활동 하나는 항목·개인 기록·이벤트·프로필 등 여러 문서를 읽고 씁니다. 한 번 누르는 것이 Firestore 쓰기 한 번을 뜻하지 않습니다. 팀원 수와 접속 빈도에 따라 읽기 사용량도 증가합니다.

## 팀과 보상

- 첫 팀을 만든 사람이 팀장입니다.
- 팀원도 다른 사람을 초대할 수 있습니다. 새 팀원의 `parentUid`에 초대한 사람의 UID를 저장합니다. 기존 팀원의 부모 관계는 바뀌지 않습니다.
- 공유 항목과 댓글은 팀 전체에서 보입니다. 부모 관계는 조직 관계이며 비공개 하위 그룹을 뜻하지 않습니다.
- 초대는 암호학적 무작위 48자리 토큰입니다. 정확한 링크로만 접근할 수 있고 초대 목록 전체 조회는 거부됩니다. 링크는 복사해서 직접 공유합니다.
- 공유 기록: **10 XP + 2 G**, 마무리: 단계에 관계없이 **20 XP + 5 G**. 100 XP마다 레벨 업합니다.
- 꽃밭·랜턴·분수는 각각 20/50/100 G로 구매합니다. **내 방 꾸미기**에서 소품을 끌어 배치하고, 보관·재배치하거나 아침/노을/밤 분위기를 고를 수 있습니다. 같은 아이템의 중복 구매는 차감하지 않습니다. 구매 내역은 계정에, 위치와 분위기는 현재 기기에 저장합니다.
- 비밀 항목은 서버에 보내지 않으므로 계정 보상에는 포함하지 않습니다.

### 방 꾸미기 소품 21종

기존 세 가지 구매가 각각 **7종 세트**로 확장됩니다. 이미 구매한 세트도 새 소품 6종이 추가로 열리며 재구매하거나 코인을 다시 쓸 필요가 없습니다.

- 꽃밭 세트 20 G: 꽃밭, 다육이, 몬스테라, 책, 감사 일기장, 토끼 찻잔, 꽃병
- 별빛 세트 50 G: 랜턴, 토끼 인형, 곰돌이, 고양이 쿠션, 별 쿠션, 달 조명, 별 가랜드
- 소망 세트 100 G: 분수, 소파, 러그, 책장, 테이블, 토끼 의자, 오두막 시계

모바일 가게에서 종류별 필터와 이름 검색을 사용합니다. 새 소품은 방에 자동으로 쌓이지 않으며 「방에 배치」로 원하는 것만 꺼냅니다. 큰 가구도 화면 안에서 이동하도록 경계를 적용했습니다. `npm run test:room`으로 세트 구매·기존 소유권·추가 소품 배치·검색·기기 저장·모바일 폭을 검증합니다.

## 비밀 기록

`pray:secrets:<사용자 UID>`라는 브라우저 로컬 저장소 키를 사용합니다. 체험 계정과 실제 계정은 별도이며, 로그아웃하면 이전 계정의 비밀 기록을 화면에서 제거합니다.

기기 저장은 암호화 금고가 아닙니다. 해당 브라우저 프로필에 접근할 수 있는 사람은 저장소를 검사할 수 있습니다. 브라우저 데이터 삭제, 다른 기기/브라우저 이동 시 자동 복원되지 않습니다. 설정에서 JSON 백업을 다운로드할 수 있으며, 현재 다시 가져오기 UI는 없습니다.

## Firebase Spark 연결

1. Firebase 프로젝트를 만들고 **Spark 무료 요금제**로 유지합니다. Blaze로 올리거나 결제 계정을 연결할 필요가 없습니다.
2. Authentication에서 Google 로그인 제공자를 활성화합니다.
3. Firestore Standard 데이터베이스를 만들고 웹 앱을 등록합니다.
4. `.env.example`을 `.env.local`로 복사하고 웹 구성의 `apiKey`, `authDomain`, `projectId`, `appId`를 채웁니다. 서비스 계정 비밀키를 넣지 않습니다.
5. 빌드 후 **규칙과 Hosting만** 배포합니다.

```bash
npm ci
npm run build
npx firebase-tools login
npx firebase-tools deploy --project YOUR_PROJECT_ID --only firestore:rules,hosting
```

6. Authentication 승인된 도메인에서 Hosting 도메인을 확인합니다. 로컬 로그인 테스트에는 `localhost`도 확인합니다.
7. 서로 다른 Google 계정 두 개로 팀 생성 → 초대 → 가입 → 공유 → 각자 기록과 마무리를 확인합니다.

GitHub Pages 빌드는 저장소의 **Settings → Secrets and variables → Actions → Variables**에서 `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`를 읽습니다. 이 값들은 브라우저용 공개 구성입니다. `.env.local`은 Git에 올리지 않습니다. Firebase Authentication 승인된 도메인에는 `patrickdfg.github.io`가 포함되어야 합니다.

환경변수를 바꾸면 개발 서버 재시작 또는 재빌드가 필요합니다. 프런트엔드와 같은 버전의 `firestore.rules`를 함께 배포해야 합니다. 이전 Cloud Functions 버전의 실제 데이터를 연결했던 경우 스키마 마이그레이션이 필요하며, 새 Spark 프로젝트를 기본 대상으로 합니다.

## 권한과 동시성

- 프로필은 본인만 읽습니다. XP·코인은 임의 변경할 수 없고, 동일 요청에서 생성되는 활동 이벤트와 연결된 정확한 보상만 허용합니다.
- 이벤트·기록·보상·공유 횟수는 원자적 트랜잭션으로 갱신합니다. 새 이벤트만 보상하며 완료한 항목을 다시 완료할 수 없습니다.
- 팀 생성, 초대 사용 수, 팀원 관계, 팀별 인원·항목 수는 함께 기록되고 규칙에서 확인합니다.
- 팀원만 공유 항목을 읽고 기록합니다. 댓글은 본인 프로필 이름으로 추가만 가능하며 다른 댓글의 수정·삭제는 거부됩니다.
- 개인별 완료 결과는 본인 키만 추가할 수 있습니다. 다른 사람의 결과와 원문을 바꾸는 요청은 거부됩니다.
- 공유 API는 비밀 항목을 받지 않으며, 직접 Firestore에 보내는 비밀 표시도 규칙에서 거부합니다.
- 충돌 시 일부 교차 문서 검증이 일시 거부될 수 있어 공유 변경은 최대 3회 재시도합니다. 이벤트 ID가 중복 보상을 방지합니다.

## 검증

```bash
npm test
npm run build
npm run test:rules
# 별도 터미널에서 개발 서버 실행 후:
npm run test:browser
```

공개 배포를 검사하려면 `APP_URL=https://patrickdfg.github.io/pray/` 환경변수를 지정하고 `npm run test:browser`를 실행합니다. PowerShell에서는 `$env:APP_URL='https://patrickdfg.github.io/pray/'`로 지정합니다.

규칙 테스트에는 **Java 21 이상**이 필요합니다. Firebase CLI가 데모 프로젝트 `demo-pray-spark`의 로컬 Firestore 에뮬레이터를 실행하며 실제 프로젝트·결제 계정은 사용하지 않습니다.

- 도메인 단위 테스트: 기록 간격, 완료 범위, 평균, 하루 200회 제한 및 한국 자정 초기화.
- 실제 Firestore 에뮬레이터: 인증, 팀 생성, 초대 관계, 외부 팀 차단, 비밀 항목 거부, 중복 보상, 독립 완료, 댓글 보호, 구매 잔액, 동시 기록, 한도 우회 차단, 만료 초대 등.
- Chrome 브라우저: 등록, 기록, 공격 효과, 댓글, 완료, 보관함, 비밀 저장·새로고침, 모바일 화면, 초대 안내, 아이템 구매.
- GitHub Actions: 단위 테스트, 프로덕션 빌드, Java 21 기반 규칙 통합 테스트.

운영 주소에서 실제 Google 로그인과 첫 가입 프로필의 Firestore 저장을 확인했습니다. 별도의 Google 계정 두 개를 사용하는 팀 초대·공유 운영 점검은 추가로 진행할 수 있습니다. `tests/auth-browser.cjs`는 실제 배포의 가입 버튼과 모바일 진입 화면을 확인하며 Google 계정 인증을 자동으로 대신하지 않습니다.

- `src/main.tsx`: 화면과 기기 체험 모드
- `src/garden.css`: 토끼의 포근한 방 테마와 모든 화면의 최종 반응형 규칙
- `src/quest.css`: 기존 기본 구조와 애니메이션
- `src/domain.ts`: 기록·통계·체험 보상 한도
- `src/spark.ts`: Spark용 Firestore 트랜잭션
- `src/cloud.ts`: 선택적 Firebase 연결과 최대 100개 구독
- `firestore.rules`: 팀 권한·보상·한도 규칙
- `public/sheep-hero.webp`, `public/slime.webp`: 새로 제작한 투명 캐릭터
- [ASSETS.md](ASSETS.md): 캐릭터 제작 도구와 프롬프트
